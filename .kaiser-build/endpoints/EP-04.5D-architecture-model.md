# EP-04.5D: Architecture Model

**Date**: 2026-09-04
**Phase**: P04.5 - Network + Architecture + Callflow
**Subphase**: EP-04.5D

## Summary

Created normalized architecture model for logical/software architecture detection.

## Important Distinction

This is **LOGICAL** architecture (ViewControllers, Services, etc.), NOT **PHYSICAL** (Frameworks, Dylibs).

| Aspect | P04.4 | P04.5 |
|--------|-------|-------|
| Type | Physical | Logical |
| Model | ComponentGraph | ArchitectureModel |
| Content | Frameworks, Dylibs, Extensions | ViewControllers, Services, etc. |
| Edges | CONTAINS, LOADS | delegates_to, uses, creates |

## Architecture Roles

| Role | Description |
|------|-------------|
| VIEW_CONTROLLER | UI controller |
| VIEW_MODEL | MVVM view model |
| MODEL | Data model |
| SERVICE | Business logic service |
| REPOSITORY | Data access layer |
| MANAGER | Manager class |
| CLIENT | API/client class |
| ROUTER | Navigation router |
| COORDINATOR | Flow coordinator |
| DELEGATE | Delegate pattern |
| HANDLER | Event/data handler |
| PROVIDER | Provider pattern |
| INTERACTOR | Clean architecture interactor |
| PRESENTER | Presenter |
| WORKER | Background worker |
| UNKNOWN | Cannot classify |

## Evidence Levels

| Level | Description |
|-------|-------------|
| HEURISTIC | Name-based only |
| REFERENCE | References to/from |
| STRUCTURAL | Inheritance, protocols |
| CORRELATED | Multiple evidence types |
| VERIFIED | Confirmed by analysis |

## Classification Approach

1. **Name-based heuristics** (weakest)
2. **Protocol adoption** (stronger)
3. **Inheritance** (strongest)

Classification level is explicit in `evidence_level`.

## Alternative Roles

When heuristic classification is uncertain, alternative roles are recorded.
