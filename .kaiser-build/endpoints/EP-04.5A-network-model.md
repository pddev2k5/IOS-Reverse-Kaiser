# EP-04.5A: Network Model

**Date**: 2026-09-04
**Phase**: P04.5 - Network + Architecture + Callflow
**Subphase**: P04.5A - Network Model

## Summary

Created normalized network model for endpoint discovery and evidence tracking.

## Model Entities

| Entity | Purpose |
|--------|---------|
| EvidenceStrength | STRING_HINT, REFERENCE, STRUCTURAL, CORRELATED, VERIFIED |
| HTTPMethod | GET, POST, PUT, DELETE, PATCH, etc. |
| NetworkFramework | URLSession, CFNetwork, Alamofire, AFNetworking, etc. |
| FrameworkPresence | EMBEDDED, USAGE_SUSPECTED, USAGE_CONFIRMED |
| EndpointCandidate | Network endpoint with evidence strength |
| PathCandidate | Path discovered separately from full URL |
| HeaderCandidate | HTTP header with producer tracking |
| ParameterCandidate | Request parameter |
| RequestBuilder | Request construction metadata |
| NetworkFrameworkPresence | Framework presence record |

## Key Design Decisions

1. **Evidence Strength Hierarchy**
   - STRING_HINT < REFERENCE < STRUCTURAL < CORRELATED < VERIFIED
   - Endpoint is not VERIFIED without evidence

2. **Framework Presence ≠ Usage**
   - Framework binary present ≠ app uses it
   - Presence level tracked separately

3. **Header/Parameter Producers Unresolved**
   - Header candidates discovered without claiming producer
   - producer = None until evidence

4. **Base URL and Path Separation**
   - Can discover path without full URL
   - Each has separate candidate ID
