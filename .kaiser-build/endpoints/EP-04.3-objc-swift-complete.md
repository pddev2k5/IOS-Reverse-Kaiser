## Evidence Strength Model

Each capability distinguishes evidence quality:

| Level | Meaning |
|-------|---------|
| STRUCTURAL | Recovered from runtime structures |
| SYMBOL | From symbol table |
| MANGLED_SYMBOL | From mangled Swift symbols |
| REFERENCE | From reference pointers |
| STRING_HINT | From strings only |

## Address Model

Addresses have explicit types to avoid mixing semantics:

| Type | Description |
|------|-------------|
| FILE_OFFSET | Offset in the file |
| VIRTUAL_ADDRESS | Virtual address |
| VM_ADDRESS | VM address |
| RELATIVE_OFFSET | Relative offset |
| SLICE_RELATIVE | Slice-relative offset |

## Design Decisions

1. **No call relationship fabrication** - objc.deep_metadata tracks metadata and reference relationships, not invented calls
2. **Failed demangle is valid** - swift.demangle returns partial success for failed demangling, not failure
3. **Evidence strength explicit** - Every entity carries its evidence source
4. **Address types labeled** - No mixing file offsets with virtual addresses
5. **Pure Python adapters** - Cross-platform without external dependencies

## Known Limitations

1. **Structural parsing is basic** - Full ObjC/Swift metadata parsing requires more complex structure traversal
2. **Demangling limited** - Python fallback only handles simple cases
3. **No IDA/Ghidra integration** - Outputs support future integration but don't include it
