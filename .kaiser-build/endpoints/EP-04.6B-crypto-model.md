# EP-04.6B: Crypto Model

**Date**: 2026-09-04
**Phase**: P04.6 - Crypto + Anti-analysis
**Subphase**: EP-04.6B

## Summary

Created normalized crypto model for cryptographic operation detection and analysis.

## Model Entities

| Entity | Purpose |
|--------|---------|
| EvidenceStrength | STRING_HINT, REFERENCE, STRUCTURAL, CORRELATED, VERIFIED |
| PrimitiveCategory | HASH, MAC, SYMMETRIC_CIPHER, ASYMMETRIC_CIPHER, KDF, etc. |
| Algorithm | MD5, SHA256, AES, RSA, ECDSA, etc. |
| CryptoLibrary | COMMON_CRYPTO, SECURITY_FRAMEWORK, CRYPTOKIT, OPENSSL |
| LibraryPresence | LINKED, USAGE_SUSPECTED, USAGE_CONFIRMED, UNKNOWN |
| CryptoReference | Reference to crypto symbol/API |
| CryptoOperationCandidate | Candidate crypto operation |
| KeyMaterialCandidate | Key material candidate (conservative) |
| CryptoEvidence | Individual evidence piece |
| CryptoFinding | Finding/correlation |

## Evidence Strength Hierarchy

| Level | Meaning |
|-------|---------|
| STRING_HINT | Found in strings only |
| REFERENCE | Symbol/import reference |
| STRUCTURAL | From parsing/imports |
| CORRELATED | Correlated with other evidence |
| VERIFIED | Confirmed by analysis |

## Key Design Decisions

1. **Library Presence ≠ Usage**
   - Framework linked ≠ app uses it
   - Presence tracked separately from usage

2. **String Evidence = STRING_HINT**
   - "AES" in strings alone → STRING_HINT
   - Cannot become VERIFIED without stronger evidence

3. **Algorithm = UNKNOWN without evidence**
   - Don't claim specific algorithm without evidence

4. **Key Material = Conservative**
   - Do NOT claim actual key values
   - Record evidence location only
