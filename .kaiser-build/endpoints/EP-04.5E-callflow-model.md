# EP-04.5E: Callflow Model

**Date**: 2026-09-04
**Phase**: P04.5 - Network + Architecture + Callflow
**Subphase**: EP-04.5E

## Summary

Created callflow model for evidenced call relationships from metadata.

## Important

This represents **evidenced** call relationships, NOT speculative call graphs.

## Core Entities

| Entity | Purpose |
|--------|---------|
| FlowAnchor | Analysis anchor (endpoint, selector, function) |
| FunctionNode | Function/method node |
| CallEdge | Call relationship edge |
| UnresolvedTarget | Call target that couldn't be resolved |
| CallFlow | Complete callflow model |

## Edge Types

| Type | Meaning |
|------|---------|
| CONFIRMED_CALL | Proven call |
| REFERENCE | Selector/symbol reference |
| METADATA_RELATIONSHIP | From metadata |
| POSSIBLE_CALL | Possible but not confirmed |
| UNRESOLVED | Target could not be resolved |

## Anchor Types

| Type | Description |
|------|-------------|
| ENDPOINT | Network endpoint string |
| SELECTOR | ObjC selector |
| CLASS | Class name |
| FUNCTION | Function name |
| SYMBOL | Symbol |
| HEADER | HTTP header |
| CRYPTO | Crypto primitive |
| ARCHITECTURE | Architecture component |

## Anchor-Driven Reconstruction

```
anchor (endpoint, selector, etc.)
  ↓
references (from metadata)
  ↓
candidate functions/methods
  ↓
evidenced edges
  ↓
flow graph
  ↓
unresolved gaps (explicit)
```

## Key Invariants

1. Unresolved targets remain explicit
2. Selector reference ≠ confirmed call
3. References should be labeled REFERENCE
4. Only CONFIRMED_CALL with strong evidence
