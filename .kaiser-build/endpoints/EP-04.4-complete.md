## Component Graph Model

### Graph Structure
- **Root**: Application component
- **Nodes**: Framework, Dylib, Extension components
- **Edges**: CONTAINS, LOADS, WEAK_LOADS, REEXPORTS

### Eligible Executables
Canonical set of executable components for dump-full:
```
eligible_executables[]:
  - Main app executable
  - Embedded framework executables
  - Embedded dylib executables
  - Extension executables
  - Nested framework executables in extensions
```

### Key Design Decisions

1. **Containment ≠ Linkage**
   - CONTAINS: Bundle structure (PlugIns, Frameworks dirs)
   - LOADS: Mach-O LC_LOAD_DYLIB relationships

2. **System Dependencies Separate**
   - System frameworks (UIKit, Foundation) tracked separately
   - Not counted in eligible_executables

3. **No Fabricated Components**
   - Unresolved dependencies remain unresolved
   - No fake UIKit/Foundation components created

4. **@rpath Resolution**
   - Evidence-driven resolution
   - Maintains unresolved state when resolution fails

5. **Stable Component IDs**
   - Based on content hash, not paths
   - Deterministic across runs
