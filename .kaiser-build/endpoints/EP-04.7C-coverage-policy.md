# EP-04.7C: Coverage Policy

**Date**: 2026-09-04
**Phase**: P04.7 - Reporting + Coverage
**Subphase**: EP-04.7C

## Summary

Created declarative coverage policies for different workflows and depths.

## Workflows

| Workflow | Purpose |
|----------|---------|
| UNPACK | Minimal extraction |
| DUMP | Standard binary analysis |
| STANDARD | Default analysis |
| FULL | Maximum coverage |
| NETWORK | Network-focused |
| CRYPTO | Crypto-focused |

## Depths

| Depth | Purpose |
|-------|---------|
| QUICK | Minimal dimensions |
| STANDARD | Standard dimensions |
| DEEP | Extended dimensions |
| FULL | All dimensions |

## Policy Examples

### Full Dump
```yaml
workflow: dump
depth: full
required_dimensions:
  - binary
  - architecture_slice
  - macho_structure
  - imports
  - exports
  - symbols
  - strings
  - objc_metadata
  - swift_metadata
  - frameworks
  - dylibs
  - extensions
```

### Network Full
```yaml
workflow: network
depth: full
required_dimensions:
  - binary
  - architecture_slice
  - macho_structure
  - network
  - architecture
  - callflow
  - crypto
  - anti_analysis
```

## Key Design Decisions

1. **Declarative, not imperative**
   - Policy defines required dimensions
   - Not hardcoded in report generation

2. **Workflow + Depth combination**
   - Each combination has explicit policy
   - `dump.full` differs from `standard.full`

3. **Optional dimensions tracked**
   - Some dimensions are optional per workflow
   - Tracked but not required
